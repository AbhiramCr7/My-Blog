Full traffic path for one HTTPS page

1
You type https://shop.test. Browser is set to proxy 127.0.0.1:8080.
2
Browser → Burp: CONNECT shop.test:443. Burp: 200 Connection Established.
3
Browser starts TLS with Burp. SNI says shop.test. Burp mints a shop.test cert, signed by Burp CA.
4
Browser trusts it (because you installed the CA). Lock A is up. HTTP can now flow.
5
Burp opens a real TLS session to shop.test (Lock B) and gets the real server cert.
6
Browser sends GET / HTTP/1.1 inside Lock A. Burp decrypts it. You see it in HTTP history.
7
If Intercept is on, Burp pauses here. You can edit headers or body, then Forward.
8
Burp re-encrypts the (maybe edited) request with Lock B and sends it to the real server.
9
Server reply comes back inside Lock B. Burp decrypts, maybe intercepts again, encrypts with Lock A.
10
Browser renders the page. It never saw Lock B. The server never saw Lock A.
