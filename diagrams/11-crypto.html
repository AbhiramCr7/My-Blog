One request — decrypt, then encrypt again

A
Browser encrypts GET /login with TLS Connection A keys. Wire Browser→Burp is ciphertext.
A→
Burp terminates TLS Connection A. Inside Burp the bytes are normal HTTP. This is what you see.
B
Burp encrypts that same HTTP with TLS Connection B keys. Wire Burp→server is ciphertext again.
B→
The target decrypts TLS Connection B. It never had Connection A state. Reply does the same in reverse.

AES (or whatever the handshake picked) is not “broken”. Burp is a valid endpoint of both handshakes, so it is allowed to decrypt. Two rooms, two keys, Burp has a door into both.
